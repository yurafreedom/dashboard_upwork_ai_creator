## 1. Определи среду и подключи MCP

Сначала установи, где выполняется задача: локальный Codex на моём компьютере, CLI/IDE либо ChatGPT Work Cloud. Не выдавай настройку в облачном контейнере за настройку моего Mac. Не предполагай, что авторизация и конфигурация автоматически переносятся между локальной и облачной средой.

Официальный сервер: https://mcp.upwork.com/mcp

Проверь актуальные инструкции:
- https://www.upwork.com/ai/mcp
- https://support.upwork.com/hc/en-us/articles/55446516654611-How-to-use-Upwork-with-AI-agents-through-MCP
- https://learn.chatgpt.com/docs/extend/mcp
- https://learn.chatgpt.com/docs/automations
- https://learn.chatgpt.com/docs/notifications
- https://support.upwork.com/hc/en-us/articles/56577997707923-Rate-limits-for-Upwork-MCP
- https://www.upwork.com/legal#apimcpterms

В локальном Codex проверь установленную версию и справку `codex mcp`. Проверь существующую запись upwork, не раскрывая секретов и не перезаписывая другие MCP. Если записи нет, используй поддерживаемую установленной версией команду:

```bash
codex mcp add upwork --url https://mcp.upwork.com/mcp
```

Если авторизация не завершилась при добавлении, выполни:

```bash
codex mcp login upwork
```

Я самостоятельно пройду вход Upwork/OAuth в браузере. Не проси пароль, cookie, access token или refresh token в чате. Не извлекай авторизацию из браузера. Не устанавливай сторонние скрейперы или одноимённые неофициальные серверы. Не добавляй экспериментальные флаги из старых инструкций без проверки поддержки текущей версией.

Если нужен ручной конфиг, минимальная запись:

```toml
[mcp_servers.upwork]
url = "https://mcp.upwork.com/mcp"
```

Перед правкой существующего конфига сделай защищённую локальную резервную копию; не включай её в отчёт или синхронизацию. Если Upwork уже установлен через официальный plugin, используй это подключение и не создавай дубль.

В облачной среде используй доступное официальное подключение/плагин и отдельную авторизацию в этой среде. Если оно недоступно, подготовь все рабочие файлы, сообщи точное необходимое действие пользователя и не заявляй об успешном подключении.

## 2. Доступ и доказательство работоспособности

Получи фактический каталог инструментов и их схемы. Не выдумывай названия инструментов, аргументы, поля или поддерживаемые фильтры. Для фонового поиска разреши только необходимые операции чтения. Если среда поддерживает `enabled_tools`, сформируй allowlist по реально полученному каталогу, сохраняя нужные средства discovery. Если единый инструмент умеет и читать, и менять данные, одного разрешения этого инструмента недостаточно: используй доступное ограничение действий либо явно сообщи, что техническую изоляцию чтения подтвердить нельзя. В таком случае сначала оставь запуск ручным.

Никогда не отправляй предложения/сообщения, не покупай Connects, не включай boosts/Availability Badge, не принимай офферы и не изменяй профиль. Черновики составляй в ответе или файлах. Любая будущая отправка требует отдельного подтверждения конкретного текста, заказа, ставки/суммы и затрат Connects; данный запрос такого подтверждения не даёт.

После OAuth проверь реальный вызов поиска. Наличие строки в `codex mcp list` ещё не доказывает доступ к marketplace. Покажи результат подключения, доступные функции и выполненную проверку. Не выполняй тестовую платную или изменяющую данные операцию.
